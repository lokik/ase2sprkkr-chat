Changelog
=========

Version 4.0.0-beta1
-------------------

Execution and projects
~~~~~~~~~~~~~~~~~~~~~~
* New backend-independent execution framework for local calculations,
  remote SSH execution, and optional PSI/J schedulers including Slurm.
* Asynchronous calculation runners with status monitoring, cancellation
  and reconnection to running calculations.
* Persistent projects with hierarchical organization and optional
  project working directories.
* Persistent run history, recording execution state, task identity,
  input and output files, and their provenance.
* Recovery of historical SPR-KKR results using ``TaskResult.from_run``
  and ``ExecutionManager.load_result``.
* Recovery of interrupted submissions and support for resuming failed
  downloads or retrying postprocessing without resubmitting a calculation.
* Declarative file manifests for task inputs, outputs and reusable caches,
  including optional files and wildcard file patterns.
* File staging and configurable synchronization between local and remote
  working directories, with integrity checks for recovered files.
* Host-specific MPI launcher detection, preferring ``srun`` inside
  Slurm allocations.

Configuration
~~~~~~~~~~~~~
* YAML-based user configuration with named execution profiles.
* Execution profiles support different local/remote backends,
  executables, MPI settings and execution resources.
* Integration with ASE's SPR-KKR calculator configuration.
* Migration of the legacy Python configuration using
  ``ase2sprkkr config --migrate``.
* Extended configuration CLI for inspecting, selecting and editing
  profiles and their settings.

Tasks and input parameters
~~~~~~~~~~~~~~~~~~~~~~~~~~
* Substantially extended and revised native SPR-KKR task definitions.
* Task identities are separated from input parameter schemas, allowing
  several tasks to share the same input format.
* Distinct ``BSFEK`` and ``BSFKK`` tasks share the BSF input schema.
* Improved native definitions for ``ARPES``, ``AIPES``, ``SPLEED`` and
  ``BAND``; experimental tasks are identified in the CLI.
* Improved support for user-defined input parameter definitions,
  named presets and canonical task identities.
* Task-specific declarations of input, output and cache files,
  including conditional file names and optional outputs.
* Improved handling of ``DATASET``, ``ADSI``, ``TAUDIR`` and
  ``TAUPATH`` in native SPR-KKR file names.
* Support for reading incomplete input files, with warnings for
  missing required values.
* Conditional requiredness and cross-section validation of input
  options, including dependent array lengths.
* Improved energy defaults and BSF k-path configuration.

Results and plotting
~~~~~~~~~~~~~~~~~~~~
* Structured SPR-KKR result files are exposed as ``ResultFile`` from
  ``ase2sprkkr`` and ``ase2sprkkr.result_files``. The top-level
  ``OutputFile`` name remains as a deprecated compatibility alias.
* SFN file reading, writing and plotting, with the ``SFNFIL`` input
  option for selecting an explicit shape-function file.
* ``TaskResult.sfn_generated`` indicates whether the SFN file was
  generated by SPR-KKR or reused.
* SCF output parsing supports runs without ``EMIN``
  (thanks to Chriss Woodgate).
* ARPES results provide all polarization spectra through
  ``ArpesResult.spectra``.
* NeXus/HDF5 export of ARPES spectra, including native axes and
  available experimental metadata.
* Interactive ARPES plotting controls for selecting scan slices.
* Improved arithmetic and copying of DOS, BSF and ARPES results.
* ``print_output`` accepts regular expressions, combinations of
  output modes and custom output listeners.
* Various fixes and improvements in result parsing and plotting.

Calculator and API
~~~~~~~~~~~~~~~~~~
* Calculation preparation and execution are separated through
  ``SPRKKR.prepare`` and ``SPRKKR.create_run``.
* Prepared calculations manage their own input files and
  execution resources.
* Explicit ``restart_scf`` option for controlling SCF restarts.
* Improved integration between calculators, persistent projects
  and historical results.
* ``ArpesResult.spc`` is deprecated in favor of ``spectra``.

Compatibility
~~~~~~~~~~~~~
* Python 3.8 support dropped; Python 3.9 or newer is required.
* Legacy execution configuration options are deprecated in
  favor of named profiles.

Internals
~~~~~~~~~
* Transactional configuration updates and cross-section validation.
* Refactored task registries, lazy schema loading and explicit
  task/output-reader associations.
* More general dependent, repeated and generated configuration values.
* Support for NumPy arrays with specified and dependent line counts.
* Improved execution lifecycle, thread safety and resource ownership.
* Durable run storage with file integrity verification and protection
  against conflicting calculations.
* Various bug fixes and compatibility improvements.
